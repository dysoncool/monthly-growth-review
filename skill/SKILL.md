# 月度成长总结（通用版 · 五格）

给一个人出他自己的月度账：这个月做成了什么、几样本事攒到第几格、哪里在漏、下一步只做一件。
**不是汇报工作量，是让他看见积累。**

## 零、出稿只有一条路（硬规则，先看这条）

**版式只有一个来源：模板文件。** 不复制模板就出稿，一律算错。

```bash
python3 scripts/check_update.py                                  # 1. 先验版本
cp templates/monthly-review-blank.html <库>/monthly-review/2026-01-月度成长总结.html   # 2. 复制
python3 scripts/check_page.py <成品>                              # 3. 自检 19 项
```

- `check_update.py` 退出码不是 0 → 先更新，别继续。落后版本出的稿会与新版不一致。
- 复制模板后**只改文字**：删掉示例句，换成真数据。
- **禁止自己写 HTML/CSS**；禁止改 `<style>` 里任何一行；不换框架、不换字体、不加减 class。
- 用户说「样式不对」→ 第一动作是跑 `check_update.py`，不是改样式。
- 自检结果要贴给用户，不许只说「已通过」。

## 一、开工前先定四件事（一次问清，别边做边问）

1. **给谁看**：本人自用，还是要发给别人。
2. **何时发**：默认每月最后一天 21:00，数据截至当日。
3. **放哪**：不许凭猜，跑 `python3 scripts/where.py` 让它给出建议路径，用户点头后 `--base` 固定（下文记作 `<库>`）。
   - 优先放进用户自己的库：已有 `principal/` 的目录 → `<库>/principal/monthly-review`
   - 找不到库才退到家目录 `~/monthly-review`
   - **禁止**放进技能安装目录、家目录根、系统盘根目录，也**禁止**自己造一个 `~/monthly-review`。
   - **退出码 2 就是要你问**：说明有多个库或没找到库。把候选路径编号发给用户，回数字即选。
   - 退出码 0 也只在「当前目录就是库」或「只有一个库」时出现，落稿前仍要问一句「放这里对吧」。
4. **从哪个月起算**：先问记录在哪、再跑连续性脚本算出最早记录月；不许默认当月，缺月先补最早那期。

## 二、五格档位（唯一口径）

| 档位 | 定义 |
|---|---|
| 刚冒头 | 第一次获得正反馈 |
| 开始积累 | 至少三次，横跨两周 |
| 初有效果 | 产生重要改变或改善 |
| 值得重视 | 有回头客，或压力期没断 |
| 略有小成 | 系统化、方法论、更轻松 |

- 一把尺，**外用与内修共用同一套解释**，不再各写一套。
- 分两组摆：**外用**（对着外面出手：交付／收费／开口／写东西／找资源）与**内修**（对自己使：手艺、身体、记录）。
- **内修单薄必须给「提醒」块**，点名缺的养神动作：读书、静坐、站桩。空着不说＝不合格。
- 档位＝存量；当月变化另记四态：**首现／不动／增强／变弱**。两栏不混。

## 三、五个数、五块（顺序不可换）

1. 标题区：`【姓名】个人月度复盘总结——YYYY 年 MM 月`（无期号、无版本号）
2. 一屏结论：一句判断（成／没成）＋三行解释
3. 四个关键数：有记录的天数／做过的事／有结果的比例／到账金额；常显不折叠，「有结果」标红
4. 五问（标题全带问号）：做成了什么／势能到哪一步／哪条路越走越省力／哪里在漏／怎样算站住
5. 收尾：只留一个动作＋起算日；页脚写数据从哪来／怎么算的／哪里缺了

**不设「钱从哪来」一节**；金额只出现在四个关键数和证据句里。

## 四、每条线怎么写

名称 ＋ 档位 ＋ 一句证据（谁＋日期＋他做了什么）＋「再往上一步：…」。
证据指不到人和日期就不写。**我方记档 ≠ 他方使用**：建档、整理、发出去都不算对方在用。

## 五、连续性：先找最早记录，再逐月对账（不许断）

**用户不会主动说「从最早的月开始」。你要先问、再扫、再说清。**

第一步，问一句：你的记录都在哪？（日记／日分析／周报／聊天记录导出／工单，各在哪个目录）

第二步，跑：

```bash
python3 scripts/check_continuity.py --base <库> --records <记录目录1> <记录目录2>
```

不给 `--records` 时，它会去月报目录旁边找 `journal / daily-signal / 日分析 / work-log / 日志 / 日记`。

第三步，把脚本给出的三句话原样说给用户：

1. 这套总结是按月连续积累的，单看一个月说明不了什么。
2. 你最早的记录在 `YYYY-MM`，所以从那一期开始。
3. 我一期一期往下补，缺的月份不会跳过。

硬规则：

- 起始月＝**最早有记录的月份**，不是当月，也不是"用户第一次找我"的那天。
- 只有聊天记录、没有文件时：让用户导出，或问出最早月份后用 `--start YYYY-MM` 钉住。
- 当期还没过完，不算缺口；上个月没出，算缺口。
- 缺多月时，从**最早缺的那期**补起，补完才做下一期。
- 一期都没出过时，先出最早那一期，再按顺序往后。
- 出完一期，登记到 `<库>/README.md` 的「已出期次」，下次靠它和脚本对账。

## 六、出稿自检

```bash
python3 scripts/check_page.py <成品.html>      # 19 项
python3 scripts/check_clean.py <成品.html>     # 脱敏：不许留真名、真金额、本机路径
python3 scripts/check_update.py               # 版本与模板是否最新、有没有被改
```

全绿再发。**发文件必须写 `MEDIA:<绝对路径>`**，漏了＝发不出去。

## 七、定时任务：说一次，以后自动

用户手动做一次之后，顺手把月末任务对齐（详见 `INSTALL.md` 第 4 节）：

- 每月最后一天 21:00 触发（cron `0 21 28-31 * *`），非月末静默；
- 启动先跑连续性检查，缺月补月；
- 当月已出过就跳过，不重复发；
- **失败不许静默**：出错要发一句「今晚没出成，原因是 X」。

## 八、语言

全篇人话，零黑话；每句不超过 30 字；不写鼓励、不做价值观评判；不夸人，也不贬人。

## 九、出问题先体检

样式不对、找不到文件、不知道装了几份：

```bash
python3 scripts/doctor.py            # 装了哪几份、各自版本、样式是否一致、月报散落何处
python3 scripts/doctor.py <目录>     # 加扫指定目录
```

只读不改。多份并存时 agent 可能读到旧那份，先删/移走多余的，再出稿。
